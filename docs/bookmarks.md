# 书签导入

入口在设置页「浏览器书签」，读 Chrome / Edge / Firefox / Safari 导出的 `bookmarks.html`。
解析在 `src/lib/bookmarks/parse.ts`，映射在 `plan.ts`，落库在 `import.ts`。

## 解析

自己写的状态机，不引依赖：按序扫标签，属性值里的 `>` 由引号护住，目录靠 `<DL>` 栈维护，
`<DD>` 归到上一条书签当描述。标题里的行内标签（Firefox 会插 `<B>`）继续收集文字，不会被截断；
实体解码含十进制与十六进制。浏览器导出里常见的未闭合 `<DL><p>` 也能读。

## 映射

| 书签里的位置                                               | 落到                                                |
| ---------------------------------------------------------- | --------------------------------------------------- |
| 一级目录                                                   | 分类                                                |
| 二级及更深的目录                                           | 标签（每一级各一个，`A/B/C` → 分类 A、标签 B 与 C） |
| 顶层散着的书签                                             | 未分类                                              |
| 浏览器自带的顶层目录（书签栏 / 其他书签 / Bookmarks bar…） | 忽略，下钻到里面的内容                              |

「其他书签」「收藏夹」这类名字在第一层一律当浏览器的壳忽略掉。用户真在顶层建一个同名目录会被吃掉，
预览里会写明忽略了哪些。

截断：标题 80 字、描述 300 字、分类名 40、标签 30、每条最多 12 个标签。`http` / `https` 之外的
网址（`javascript:` 等）不写入，单独列出来。文件上限 4 MB，一次最多 5000 条。

## 重复

去重键是「分类 + 网址」：

- 同一个网址出现在两个分类里：各建一条，两个分类里都看得到。跨分类各建一条是刻意的 ——
  合并成一条会让另一个分类少一条。预览里单独提示有多少个这样的网址、多出多少条。
- 同一个网址在同一个分类里出现两次：只留第一次。
- 库里已经有且就在那个分类里：默认跳过；打开「覆盖已有条目」则用书签里的标题与描述更新它，
  标签是并进去而不是换掉 —— 用户自己打的标签不会丢。

## 预览与写入

选好文件先出预览（`POST /api/bookmarks/preview`）：每个顶层目录一组，组内带统计（分类 / 标签 /
读不了的行 / 样例）。勾选某些目录时前端只做加法（`mergePreview`），不再跑一趟接口。

条目明细留在服务端，导入时按同一份文件重算计划（`POST /api/bookmarks/import`），预览与写入必然
一致，也不需要为一次导入引入临时存储。分批导入天然成立：不同目录分几次导，已导过的那批按去重键
不会重复进来。

分类与标签按名字匹配、不区分大小写，库里已有就复用。只新增与更新，不删除任何现有内容。

图标不在导入时抓 —— 几百条会把外网拉爆，交给首页按需缓存。
