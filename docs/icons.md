# 图标

代码在 `src/lib/icons/`（抓取、缓存、上传、图标库）与 `src/components/icons/`（渲染与选择器）。

## 来源

条目的图标类型存在 `items.icon_type`：

| 类型      | 说明                                                   |
| --------- | ------------------------------------------------------ |
| `favicon` | 从站点抓，候选按下面的顺序排队                         |
| `upload`  | 手动上传的文件，以及从图标库里挑中后下载到本地的那一张 |
| `emoji`   | 内置表 `emoji.ts`（114 条，中英关键词）                |
| `lucide`  | 本地登记表里的 Lucide 图标，前端直接渲染               |
| `none`    | 不显示图标，用标题首字母兜底                           |

`icon_type` 里还留着早期预留的 `simple-icons`、`iconify` 两个取值，现在没有代码写入它们 —— 从图标库
挑中的那一张一律按 `upload` 存，跟着备份走。

从图标库挑中的那张与手动上传的文件都放在数据库同级的 `uploads/`。前者以来源为文件名前缀
（`simple-icons-github-181717_<hash>.svg`），哈希取自图片内容：同一张图重复挑不会堆文件，
上游换了内容就换一个新名字。

## 抓取

取图顺序在 `sources.ts`，服务端按它去问，选择器也按它显示「这一张是谁给的」：

1. 页面里 `<link rel="icon">` 声明的
2. PWA manifest 里声明的
3. `/favicon.ico`
4. favicon.im、icon.horse（第三方，卡片上会标出来，`FAVICON_FALLBACK_SOURCES=false` 可关）

| 接口                                  | 用途                                               |
| ------------------------------------- | -------------------------------------------------- |
| `GET /api/icons/favicon?item=<id>`    | 条目图标的代理地址，只接受条目编号                 |
| `GET /api/icons/candidates?url=`      | 列候选，逐个来源给状态                             |
| `GET /api/icons/resolve?url=&source=` | 取某一来源的画面                                   |
| `POST /api/icons/upload`              | 上传（PNG / JPG / WEBP / SVG，512 KB 上限）        |
| `GET /api/icons/file/<name>`          | 读上传目录里的文件；匿名只拿得到公开条目在用的那份 |

候选状态分三种：`ok`、`placeholder`（服务活着，但只回它自己那张「查不到」占位图）、`miss`。
占位图在服务端被认出来丢掉，不会冒充站点图标。取不到时回一张 1×1 的透明 PNG —— 不是 404，
控制台不会多一条红线；前端始终垫着标题首字母，真取到图标才收起来。

代理接口只接受条目编号，匿名访问者不能拿它当扫描内网的跳板。出站抓取过 `net/fetch.ts`
（4s 超时、最多 3 跳）与 `icons/egress.ts`（拒绝回环、link-local 与保留地址，逐跳校验跳转目标）；
`FAVICON_ALLOW_PRIVATE_HOSTS=true` 时才允许抓内网地址。

结果按「站点 + 来源」落盘 7 天（`<数据库目录>/favicon-cache/`），失败也短期缓存。图标地址上带一个
`v` 变更标记：换了来源就是一条新地址，否则浏览器会一直拿 7 天前那份，看着像「保存没生效」。

自动获取只在**打开面板之后新输入的网址**上触发，同一个网址只抓一次。打开面板时就有的那个网址不抓
（编辑已有条目重开面板属于这种），想看别的候选点「获取图标」。

## 图标遮罩、跟随主题、摆法

三个按条目的开关，存在 `items` 上，跟着备份走：

- `icon_plate`（图标遮罩）：图标底下那层玻璃底与描边。应用类图标自带圆角外形，套上就是大圆套小圆，
  所以可以按条目关掉。关掉后格子尺寸不变，只是不再画那层底。
- `icon_mono`（跟随主题）：只管深色那一套。深色下把这张 SVG 当 CSS 蒙版、颜色交给 `currentColor`，
  黑图在深色主题里才不会消失；浅色下按原样显示。两个主题各渲染一份，用 CSS 的 `dark:` 切换。
  只对 SVG 生效 —— 位图的 alpha 是整个方块，蒙出来是一块实心色。
- `icon_fit`（摆法）：`contain` 原样（默认）/ `auto` 自动裁边 / `cover` 裁剪铺满 / `fill` 拉伸铺满。
  空值表示跟随设置页里的默认（`settings` 表的 `icon_fit`）。可选值只在 `src/lib/icons/fit.ts` 定义，
  schema 与选择器都从那里取。

摆法的换算在 `fit.ts` 的 `trimTransform`（纯函数，有单测）：把图缩到 96×96 的画布上数不透明像素的
范围，换算成 `scale + translate`。只在图案占画布 34%–98% 之间动手，放大封顶 2 倍，裁完多铺 3%
（量出来的范围总有两三个像素的误差，正好填满在屏幕上看还是差一条细边）。图片都走本站代理，同源，
画布读得出来；远端地址会抛，按「量不出来」退回原样。

图形大小按盒子算：盒子声明 `container-type: size`，图形用容器单位 `cqh`。开遮罩 72%，关掉 88%，
填满那三档 100%。后三档不画描边 —— 描边画在盒子内侧，留着就永远差一圈。

Emoji 不套遮罩，选择器里那个开关对它不出现；字号取图片类的 0.8 倍，按行内盒居中摆着。

## 图标库

`src/lib/icons/library/`。默认三套，按搜索结果的优先级排：

| 库           | 数据来源                     | 颜色                                 |
| ------------ | ---------------------------- | ------------------------------------ |
| Simple Icons | npm 包（CC0），装在本地      | 每个图标自带品牌色 `hex`，也可选黑白 |
| Iconify      | 官方 `search` / `svg` 接口   | 单色套件可改色，彩色套件保持原样     |
| Lucide       | 本地登记表，前端直接渲染组件 | 跟着主题走，不用下载                 |

搜索框在那排图标库胶囊上面：关键词只输一遍，换库接着搜同一个词；打开面板时按标题或域名预填一个
最像名字的词（中文标题取域名）。一页 60 个，底部可以「显示更多」接着往下要。没有关键词就不发请求。

挑中的那张下载到 `uploads/`，之后就是一张普通的本地图片：离线能显示，也不再看那个库的脸色。

Simple Icons 是单色图标，颜色用它的 `hex`，品牌标志的商标权属于各品牌（挑选时悬停能看到品牌自己的
规范链接）；Iconify 的接口免费但要求缓存、不要当批量下载口用，各套图标集许可不同，搜索结果里标了出来。
仓库里不放别人的图标本体。

## 自建图标集

填一份 JSON 的地址（`{name, description, icons: [{name, url}]}`，也接受数组或 `{名字: 地址}`），
抓回来只把清单存进 `icon_sets`（跟着备份走），图标本体仍在原图床，挑中哪张才下载哪张。
地址在 `raw.githubusercontent.com` 上时可以勾「镜像加速」改走 jsDelivr。设置页「图标库」里增删与重抓，
编辑条目的选择器里也能用「+ 图标集」直接加。
