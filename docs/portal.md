# 首页与数据

## 一次请求拿到什么

首页是服务端组件，数据来自 `getPortalData({ includePrivate })`（`src/lib/portal/queries.ts`）：

```ts
type PortalData = {
  categories: PortalCategory[];
  items: PortalItem[];
  defaultIconFit: IconFitId;
};
```

`includePrivate` 由会话决定。匿名访客的响应里不含 private 条目，也不含「不在首页显示」的分类
及其条目 —— 过滤在服务端做，前端隐藏不算权限控制。条目的可见性以自身为准，分类的 `visibility`
只是新建条目时的默认值。

## 分区与布局

首页按分类分区。每个分区用哪套布局存在分类上（`categories.layout`，空值即卡片），三种布局共用一份
网格参数（`src/lib/settings/homepage.ts` 的 `GRID_CLASS`），公开视图与编辑视图不会各写一套。

- 卡片：图标在上、描述两行；手机两列、桌面三列。
- 列表：一行一条三行文字，域名紧随标题，描述独占一行，标签在描述下方；一行不低于 88px。
  窄屏不显示域名。
- 紧凑：只有图标与标题的小方块，手机三列、桌面六列。

分类导航是搜索框下面一排横向滚动的胶囊，只显示标记为「显示在首页」的分类。桌面没有触摸滑动，
所以整排支持按住拖动（Pointer 事件 + 指针捕获，移动超过 4px 才算拖动，并吃掉随后的那次点击，
免得松手顺手切了分类）；两端在还有内容时浮出圆形箭头，滚到中间时两头渐隐；装得下时整排居中，
箭头与渐隐都不出现。

标签显示几个不按固定个数切：先把放得下的标签均分到各行（3 + 2 好过 4 + 1），放不下的才在行末
收成 `+N`。分行由纯函数 `planTagRows` 算（`src/lib/portal/tags.ts`），宽度取自一层不可见的量尺。

## 搜索

在标题、描述、网址、域名、标签与分类里即时匹配（`src/lib/portal/search.ts`），在前端过滤已经
下发的数据，不重新请求。搜索状态下不开放拖动 —— 一部分结果不能被当成完整顺序写回。

## 外观

- 配色与浅深是两个维度：六套配色只换强调色与背景光晕，中性色与卡面材质不变。选择存在 `settings`
  表，服务端渲染时写进 `<html data-palette>`，首屏不会闪。
- 材质只有一套：卡面 26px 磨砂，弹窗与菜单这类浮层 34px。
- 背景是两团模糊色斑加一层极细噪点（噪点用来打散大面积渐变的色带），两团各自以 46s / 58s 的周期
  漂移并轻微胀缩，滚动时外面再套一层视差。整套只用 `transform`；系统开启「降低动态效果」时全部静止。

## 编辑模式

开关记在 Cookie（`ivy_edit`）里：设置页打开，回到首页即可编辑。顶栏不出现管理按钮，管理入口是
设置图标。

## iOS 26 的浏览器底色

iOS 26 的 Safari 不再认 `theme-color`，浏览器底色由它在视口边缘自己找：扫 `fixed` / `sticky` 元素、
读它们的 `background-color`，读不到就回落到自己那层白，悬浮工具栏下面就会出现一条白灰带。

所以底色画在两处：`html`（画布）与环境光那层（`AmbientBackground`，铺满屏幕的 `fixed` 元素，
带 `bg-background` 与 `-z-10`），`body` 不再重复画一遍。另外两处按同一套规则处理：

- 顶栏的玻璃下沉到绝对定位的内层，`sticky` 外壳保持透明 —— 带 `backdrop-filter` 的 `sticky` 元素
  会让取样整片失效（WebKit bug 319479）。
- 根布局底边留一条 12px 的透明取样条，作为第二个可读的答案。它不占像素、挡不住内容，
  按同一规则（只有触屏 Safari 的窄屏才渲染，见 `globals.css` 的 `.safari-band`）。
