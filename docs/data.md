# 数据与备份

## 表

`src/db/schema.ts`，SQLite + Drizzle：

| 表                  | 说明                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| `users`             | 管理员（scrypt 哈希，参数随哈希存储）                                            |
| `sessions`          | 会话，只存令牌的 SHA-256 摘要                                                    |
| `categories`        | 名称、描述、排序、布局、可见性、是否显示在首页                                   |
| `items`             | 标题、描述、网址、图标（类型 / 值 / 遮罩 / 跟随主题 / 摆法）、可见性、置顶、排序 |
| `tags`、`item_tags` | 标签与关联                                                                       |
| `icon_sets`         | 自建图标集的清单（图标本体仍在原图床）                                           |
| `settings`          | 偏好：配色、图标摆法的默认值                                                     |
| `backups`           | 数据库快照的记录                                                                 |

不再被任何条目引用的标签会在保存条目时清掉，`tags` 里不留看不见的残留行。

连接是懒加载的（`src/db/client.ts`），文件不存在就自动建表。路径取 `DATABASE_PATH`，
默认 `./data/portal.db`。

迁移用 drizzle-kit 生成：改完 schema 跑 `pnpm db:generate`，产物在 `src/db/migrations/`
（`.sql` 加 `meta/` 快照），启动时按 `MIGRATIONS_PATH` 读。`meta/*.json` 是表结构元数据，不是数据。

## 运行时数据不在仓库里

`.gitignore` 忽略 `data/` 与 `backups/`，运行数据都在里面：

| 目录                                                       | 内容                                   |
| ---------------------------------------------------------- | -------------------------------------- |
| `data/portal.db`                                           | 分类、条目、标签、设置、自建图标集清单 |
| `data/uploads/`                                            | 挑中的与上传的图标文件                 |
| `data/favicon-cache/`、`icon-set-cache/`、`iconify-cache/` | 抓取缓存                               |
| `backups/`                                                 | 数据库快照                             |

换图标、删条目、换内容都会在 `uploads/` 里留下用不到的旧文件：`pnpm icons:prune` 列出它们（默认只打印，
加 `--delete` 才真删；一小时以内写过的不动，认不出的文件名跳过）。

## 导出与快照

- JSON 导出（`/api/backup/export`）包含分类、条目、标签、设置与图标集。编号不写入文件，条目通过
  分类名与标签名关联，换一套部署也能对上。管理员账号与登录状态不在其中，导入后仍是当前登录状态。
- 数据库快照（`/api/backup/create`）用 `VACUUM INTO` 生成一致副本，落在数据目录上一层的 `backups/`，
  文件名形如 `portal-20260919-225913.db`，可以列出、下载、恢复。

恢复（`/api/backup/restore`）需要二次确认，只覆盖内容表，不会改当前管理员账号，也不会让当前会话失效。
快照是数据库的完整副本，其中含密码哈希，要放好。
